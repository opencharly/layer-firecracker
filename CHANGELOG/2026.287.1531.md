The **host posture** a microVM needs from the machine it runs on — as a `kind: local` template plus the disposable-VM bed that proves it.

**Why a template and not candy steps.** The posture is udev rules, sysctls and packet-filter work, which have no meaning inside an image build — and applying them to an operator's workstation uninvited is the one thing this layer must never do. So they live in a host template that a deploy applies *deliberately*, and the bed proves them by **nesting** a `local:` member inside a disposable VM (the canonical `check-arch-vm` → `arch-host` pattern). A posture bed never writes to your workstation.

| Piece | What it does |
|---|---|
| `firecracker-host-app` | the posture recipe: the pinned artefacts via `layer-firecracker`, then `/dev/kvm` access, then forwarding |
| **`/dev/kvm` → group-only** | a `0660` node owned by group `kvm` (a udev rule), **with the running account added to the group and that membership asserted** — the half a mode check cannot see. The account is resolved on the TARGET (`FC_VMM_USER`, else the invoking account via `SUDO_USER`); a name that does not exist FAILS the step, and root needs no group so the step says so rather than pretending. A world-writable `/dev/kvm` lets any local process reach every guest's memory and the host kernel through it — and a stock Arch cloud image ships exactly that (`crw-rw-rw-`, measured) |
| **IP forwarding** | `net.ipv4.ip_forward = 1` written as a sysctl drop-in, applied immediately, and **asserted** by the plan. The *other* half of the WI-6 finding — that host's forwarding **policy** at `DROP` while `ip_forward` was already `1` — is a packet-filter **verdict**, not a sysctl, so a drop-in cannot set it; those FORWARD/NAT rules are the deferred network half (`#3`), and this row claims only what ships |
| `check-firecracker-vm` | the **guest entity** the posture bed boots: cloud image, libvirt, `q35`. It is a reusable `kind: vm` and carries no `disposable:` because it is never deployed on its own — the BED that uses it is the one marked disposable. The renderer's default `host-passthrough` CPU plus the host's `kvm_intel nested=Y` gives that guest its own `/dev/kvm` |
| `check-firecracker-posture` | the R10 bed: that VM with a nested `local:` member deploying the template |
| `.gitignore` | adds `image/` — the per-VM build outputs (`disk.qcow2`, `seed.iso`, build stamps) a bed run writes at the repo root. They are artefacts of a run, not sources, and the sibling plugin repo ignores the same shape |
| `check-firecracker-app` | the ARTEFACT-half bed, unchanged and restored: a disposable pod. A scripted rewrite of this manifest deleted it while the docs kept telling readers to run it — `charly box validate` validates what REMAINS, so the loss was invisible to it. The manifest now checks **2 deploys**, which is what the docs say |

Everything is **idempotent** and **self-gating**: a target with no `/dev/kvm` prints why and skips rather than installing a rule that can never apply, and re-running changes nothing.

`4985b71` fixed the posture check's predicate — the third form,
and the first that is not looser than the claim it asserts ("group-accessible **and** not
world-writable"):

| predicate | what it let through |
|---|---|
| `[ "$MODE" != "666" ]` | one spelling of world-writable; `662`, `663`, `667` passed |
| `66[0-7]` | `662`, `663`, `667` still passed — every one has the **other-write** bit set |
| **`66[0145]`** | owner read+write, group read+write, no write bit for anyone else |

`667` grants read+write+execute to the world and passed a check whose entire purpose is to catch a
world-writable `/dev/kvm` — the posture defect this layer replaces, since such a node lets any local
process reach every guest's memory and the host kernel. The class is now enumerated rather than
argued: `660` accept, `661` accept, `664` accept, `665` accept; `600` reject (no group access), `662`
reject, `663` reject, `666` reject, `667` reject. The udev rule writes `0660` deterministically, so the
posture itself was never wrong — the GATE was, and a gate that passes the defect it claims to catch is
no gate at all. That is why the bed was re-run.
